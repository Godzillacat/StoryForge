## 1. 为什么做这个切片

P1a 的自动化验证全绿（127 pytest / 8 vitest / 19 项冒烟），但**真实条件下跑不通**：

- 结构化输出一次都没成立过（提示词与契约键名不一致）；
- 架构推荐必然失败（120 秒写死超时，实测任务需要 139.5 秒）；
- 回滚后新建版本会静默继承被弃用版本的内容；
- spec 承诺的「角色卡全字段编辑」只做了 1/11，「编辑故事圣经」根本没做。

模型产出质量本身**已被证明可用**。这个切片只修接线，让 P1a 真正端到端可用。

**验收判据**：作者能在真实模型下走完 P1a 验收 §1.2 的七步，全程不出现「未结构化」（除非模型确实返回了非法 JSON）。

## 3. 设计

### 3.1 提示词与输出契约的一致性

**问题**：契约要求的键名（`genre`、`options`…）从未出现在提示词里，提示词只讲中文名（题材、子类型…）。忠实执行指令的模型必然返回中文键 → 校验必败。

**根因不是「忘了同步」，而是「有两份互相独立、都要人工维护的字段清单」。** 所以修法必须消灭第二份清单，而不是补一次。

**设计**：

1. **中文名搬进契约。** 在 `output_schema_json` 的每个属性上加 JSON Schema 标准的 `title`，值为中文名（`{"genre": {"type": "string", "title": "题材"}}`）。契约成为字段名与中文名的**唯一真相**。
2. **渲染层自动生成契约说明块。** 新增 `app/runtime/contract.py`：

   ```python
   def describe_contract(schema: dict | None) -> str: ...
   ```

   从 schema 递归生成一段文本，包含：顶层与嵌套的键名、中文名、类型、是否必填、数组元素的字段。形如：

   ```
   【输出契约】返回一个 JSON 对象，键名必须用英文，结构如下：
   - genre（题材）：字符串，必填
   - options（候选方案）：数组，至少 2 项，每项包含：
       - tool（结构名）：字符串，必填
       - fit_score（适配度）：数字，必填
   ```

   只认 schema 里的 `type / properties / required / items / enum / minItems`，与校验器（`schema.py`）用同一套子集词汇。
3. **`execute_run` 追加而非改写。** 渲染完提示词后追加契约块，再作为最终 prompt 发出。**落库的 `rendered_prompt` 是追加后的完整文本** —— 调试台看到的就是真发出去的那份（D-03）。
4. **预置提示词删掉手写的字段枚举。** 灵感解析师与架构师提示词里那两处「题材、子类型、一句话前提…」与那张手写的 JSON 结构图删掉，改为一句「字段含义见【输出契约】」。字段的中文名从此只在 schema 里维护。

**为什么不用别的方式**：
- 只改提示词（把英文键名手写进去）：下次改 schema 会再犯，且嵌套结构手写易错。
- 把 schema 键改成中文：前端类型、槽位、导出都要跟着改，且中文键跨系统传递易踩编码坑。

### 3.2 请求超时可配置

**问题**：`llm.py` 的 `HttpxChatClient(timeout=120.0)` 写死；实测架构推荐需要 139.5 秒。

**设计**：

- `config.py` 的 `DEFAULT_SETTINGS` 增加 `request_timeout_seconds: 300`（留 2 倍余量）。
- 解析顺序：`model_binding_json.timeout_seconds`（角色卡级，可选）→ 全局设置 → 默认 300。
- `llm.py`：`_wrap_transport_error` 拼超时文案时带上**超时值与实际类型**（当前 httpx 的 `str(exc)` 常为空，界面上显示成「请求超时：」后面什么都没有）。

**关于流式 —— 一个我建议推翻、但请你裁决的点。**

`CLAUDE.md` §8 记的是「长任务超时应可配置、**并走流式**」。我建议**本切片只做可配置超时，流式留给 P2**，理由：

- 流式的真正收益是**长生成不会被整体超时掐死**（read timeout 变成逐 chunk 生效）。300 秒对当前观测到的 139.5 秒有 2 倍余量，P1a 的两种任务都够用。
- 代价是真实的：现有 `llm.py` 的 `stream()` **完全不解析 usage**，只累积内容。改走流式会让 `prompt_tokens / completion_tokens` 退化为估算（`estimate_tokens`），**费用记账与调试台的数字会变假** —— 而 `stream_options: {include_usage: true}` 在 OpenAI 兼容端点上的支持情况要逐个服务商验证，属于要花额度去试的事。
- P2 的正文生成本来就要把 SSE 接到前端，那时一并做流式 + usage 回填，是一次做完的正确时机。

如果你更想要现在就走流式，我按流式做，但需要先花一两次调用验证百炼的 `stream_options` 支持。

### 3.3 版本继承取当前版本

**问题**：`agent_service.create_version` 的继承源取「版本号最大」，而回滚后的「当前版本」可能不是版本号最大的那个。

**设计**：把两件事分开 ——

- **版本号**仍取 `max(version_no) + 1`（避免撞号，不变）。
- **内容继承源**改为 `agent.current_version_id` 指向的版本；若它为空或取不到，再回退到版本号最大的那个。

**回归测试**（必须在旧代码上真会失败）：v1 → 存 v2 → 回滚到 v1 → 新建 → 断言新版本的 `system_prompt` 等于 **v1** 的，而不是 v2 的。同样覆盖 `context_slots_json / output_schema_json / model_binding_json`。

### 3.4 模型绑定与角色卡字段

**后端**：

- 新增 `PATCH /api/agents/{agent_id}`，接受 `name / role_label / color / enabled`。这是目前**完全缺失**的一环（spec 要求「角色卡全字段编辑」，而这些字段连接口都没有）。
- `GET /api/slots`：从 `context.py` 的 `SLOT_REGISTRY` 生成 `[{key, label, priority, over_budget}]`。槽位清单只此一份，前端不硬编。

**前端（智能体工作室）**：

| 区域 | 字段 | 控件 |
|---|---|---|
| agent 级 | 名称、定位、颜色、启停 | 文本框 / 文本框 / 颜色输入 / 开关 |
| 版本级 | 系统提示词 | 多行文本（现有） |
| 版本级 | 绑定模型 | 服务商下拉 + 模型名文本框 |
| 版本级 | 参数档 | 下拉（严谨 / 平衡 / 发散） |
| 版本级 | 上下文槽位 | 多选 + 上下移动排序 |
| 版本级 | 输出契约 | JSON 文本域，失焦时 `JSON.parse` 校验并提示 |
| 版本级 | 触发方式 | 下拉（手动 / 协同 / 自动） |

- 保存仍走「保存为新版本」（D-06 不变），旧版本保留可回滚。
- **不做**可视化 schema 编辑器（YAGNI，JSON 文本域 + 校验足够）。
- **不做**「从服务商拉取模型列表」（需要新增代理接口，且部分服务商的 `/models` 不全）。模型名用文本框，placeholder 给出示例。

**参数档生效**不在本切片（仍属 P3）—— 本切片只让作者看得见、改得动、存得下。

### 3.5 故事圣经可编辑 + L1 手动录入

**问题**：`Architecture.tsx` 的故事圣经全是只读 `<p>`，唯一动作是「采纳并写入项目」。spec §1.2 第 6 条要求「**编辑**故事圣经并确认」；三档介入的手动档（AI 只看不说）在 L1 无路可走。

**设计**：

- 推荐结果出来后，`logline / theme / premise / ending_direction` 变为可编辑输入框；幕骨架每一幕的 `name / purpose / target_word_ratio` 可编辑，可增行、删行。
- 「采纳并写入项目」提交的是**作者编辑后的值**，不是模型原值。这是「AI 出候选、作者拍板」的落点。
- 新增「**手工建立故事圣经**」入口：项目没有推荐时，给出同一套空表单，不经 AI 直接写 `architecture` + `act`。这兑现手动档。
- 架构页补空态文案（当前一片空白，作者不知道下一步点哪）。
- 「允许标注杂交方案」不在本切片（需要先定‘杂交’在数据上怎么表达，属设计问题，另议）。

### 3.6 服务商改 / 删界面

后端 `PATCH` 与 `DELETE` 已具备（实测 DELETE 返回 204）。前端「模型与费用」页的服务商列表补「编辑」（名称 / 地址 / 密钥 / 启停）与「删除」。密钥留空表示不修改。

### 3.7 连通性测试改为真实验证

**问题**：`test_connection` 用 `model=""` 发请求，且只把 network/timeout 当失败 —— 400/401/404 全判为「连接正常」。它验的是地址可达，不是能用。

**设计**：

- `POST /api/providers/{id}/test` 接受可选的 `{"model": "..."}`：
  - 传了就用它；
  - 没传则在**绑定到该服务商的角色卡**里找第一个模型名；
  - 都没有则**不发起请求**，直接返回「请先为某个智能体绑定模型，或在此填写测试用模型」—— 省下一次无意义的调用。
- 前端在「测试连通性」旁加一个模型名输入框（已知时预填）。
- 判定规则收紧（当前实现只区分「网络错」与「其他」）：

| 情况 | 判定 |
|---|---|
| 网络不可达 / 超时 | 失败 |
| 401 / 403 | 失败（密钥无效） |
| 404 | 失败（接口地址或模型名不存在） |
| 429 | 失败（额度不足或限流） |
| 400 | 失败，**并把服务商返回的原始 message 原样附上**，让作者自己判断 |
| 200 | 成功 |

不猜「400 是不是因为模型名」—— 猜错比不猜更坏。400 一律判失败并给出原文，作者看一眼就知道是什么。

文案同时改掉泄漏英文异常的问题。

**顺带修**（都在本切片已改动的文件里）：工作室智能体按钮的「解析灵感解析师」拼接、回滚按钮对当前版本也显示、`index.html` 的标签页标题与 `lang="en"`。

## 4. 测试策略

纯逻辑必须测（pytest），UI 不写自动化测试。

| 层 | 测什么 |
|---|---|
| `contract.py` | 由 schema 生成说明块：顶层/嵌套/数组/必填/enum/minItems；无 schema 时返回空 |
| `contract.py` × `schema.py` | **跨产物一致性**（这是本切片要补的关键测试）：拿预置阵容的每一张角色卡，断言其提示词不再手写字段枚举，且 `describe_contract(schema)` 覆盖 schema 的全部 `required` 键 |
| `schema.py` | 加了 `title` 之后校验行为不变（回归） |
| `llm.py` | 超时值可注入；超时文案含超时值 |
| `execute.py` | 渲染后的 prompt **包含**契约说明块；`rendered_prompt` 落库的是含契约块的完整文本 |
| `agent_service` | 回滚后新建版本的继承源（§3.3 的回归测试） |
| `provider_service` | 连通性判定表（§3.7）逐条，用假传输层 |
| `api/agents` | `PATCH /api/agents/{id}` 的字段更新；`GET /api/slots` 覆盖 `SLOT_REGISTRY` 全部键 |

**真实模型验证**：本切片完成后，用真实服务商重跑一次「灵感解析 → 架构推荐 → 编辑故事圣经 → 采纳」，确认不再出现「未结构化」。这一步消耗额度，做之前先报预算。

## 6. 已知代价与不做的事

**预置内容的变更对已存在的库不生效。** `seed_agents` 是幂等的（已存在即跳过），所以任务 2 改了 schema 与提示词后，作者**现有库里的角色卡不会自动更新**。本切片用「重建开发库」处理（沿用 P1a 已记录的做法），正式解法是迁移框架 —— 这正是它在 `CLAUDE.md` 里被列为打包硬前置的原因，本次又给它加了一条论据。

**参数档仍不生效。** 界面能改能存，但不会影响采样参数。`param_profile` 到 `temperature` 的映射属 P3。

**费用仍显示 $0。** `compute_cost` 依赖 `model_binding_json.prices`，界面上没有配置单价的地方。属 P3 的费用记账。
