# 逻辑自检 · 因果链图 · 设计

> 二期第四项之一。D-22 把逻辑自检的三张辅助视图推到二期；本张先做**因果链图**，
> 设定投放曲线与性格漂移曲线各自另立 spec（后者的数据模型还不存在）。

## 1. 意图

作者排完一章的场景卡，真正要确认的是「这一章的因果是不是一条能走通的链」：
每一场有没有目标、有没有转折、上一场的转折有没有把下一场推起来。

场景卡现在是树里的三条文本（目标 / 冲突 / 转折），作者得逐场点开才看得到。
**因果链图把一章的场景按顺序摆成一条链**，并把「断的地方」直接标出来 ——
不是替作者判断讲不讲得通（那是逻辑自检），而是指出**结构上缺了哪一段**，
以及**逻辑自检已经在这些位置报过因果问题**。

## 2. 目标 / 非目标

**目标**

1. 按卷 → 章 → 场景，把每场画成一个节点（目标 / 转折两行），相邻场景连箭头。
2. 标出三类**断点**：
   - **缺目标**：`goal` 为空 —— 这一场不知道要干什么；
   - **缺转折**：`turn` 为空 —— 这一场没有变化，链在这里推不动；
   - **因果问题**：该场有 `open` 的、`stage=plan`、`layer=causality` 的逻辑自检问题。
3. 点节点 → 跳到结构设计并选中该场（复用现有选中逻辑）。
4. 顶部给计数：`N 场 · M 个断点`，方便一眼看哪一章最散。

**非目标**

- 不判断语义上「这个转折合不合理」—— 那是逻辑自检的 LLM 层；本图只标「有人报过」。
- 不做整本书的巨型图：一章一行，纵向堆叠，页面滚动。
- 不新增数据：全部从场景卡 + `audit_issue` 读。

**反目标**

- 不能把「缺目标」和「因果问题」画成同一种标记 —— 前者是结构空缺、作者自己能补；
  后者是模型报的问题、要去处理面板里看。
- 不能在没跑过逻辑自检时假装「没有因果问题」：图里要写「未检查」而不是绿色通过。

## 3. 方案

### 3.1 后端：一个只读投影

`GET /api/projects/{id}/causal-map`

```json
{
  "chapters": [
    {
      "id": "...", "label": "第1章 雨夜", "volume_label": "第一卷",
      "scenes": [
        {"id": "...", "seq": 0, "label": "场景1",
         "goal": "把信交给掌柜", "turn": "信是假的",
         "status": "planned", "locked": false,
         "breaks": ["missing_turn"],
         "issues": [{"id": "...", "layer": "causality", "layer_label": "因果链",
                     "severity": "major", "title": "转折没有前置因"}]}
      ]
    }
  ],
  "totals": {"scenes": 12, "breaks": 3, "chapters": 4},
  "logic_checked": true
}
```

- `breaks` 是**枚举数组**：`missing_goal` / `missing_turn` / `causality_issue`（可同时多个）。
- `issues` 只收 `check_type="logic"`、`stage="plan"`、`status="open"`、`layer="causality"`。
- `logic_checked`：项目里是否存在任何 `stage=plan` 的逻辑自检运行（`audit_issue` 的
  `check_type=logic` 行或 `generation_run` 的 `logic_check` 任务）。为 `false` 时前端显示
  「还没跑过逻辑自检，图里只标结构断点」。
- 场景锁定沿用 `effective_scene_lock`（卷/章继承），节点上标锁。

**一次查询**：先按项目取卷章场景树，再一次性取该项目全部相关 `AuditIssue`，按 `scene_id` 分组。
不做 N+1。

### 3.2 前端：一章一行

位置：结构设计页（`Chapters.tsx`）视图区，与「节奏曲线」「剧情线泳道」并列的第三个视图。

```
因果链   12 场 · 3 个断点        [未跑过逻辑自检]
第一卷 · 第1章 雨夜
┌─────────┐   ┌─────────┐   ┌─────────┐
│场景1     │ → │场景2     │ → │场景3     │
│目标：交信│   │目标：（空）│   │目标：追问│
│转折：假信│   │转折：…   │   │转折：（空）│
└─────────┘   └─────────┘   └─────────┘
   缺转折 ↑       缺目标 ↑        缺转折 ↑
```

- 每个节点固定宽高（如 180×72），章内横向滚动；章之间纵向堆叠。
- 断点样式：缺目标/缺转折 = 琥珀色左边条 + 底部小字；因果问题 = 红色小圆点 + `title` 里放问题标题。
- 点节点 → `onSelectScene(sceneId)`（结构设计页已有的选中逻辑）。
- 空章（0 场景）：显示「这一章还没有场景卡」，不画空链。

### 3.3 纯函数与测试

`frontend/src/lib/causalMap.ts`：
`buildCausalRows(payload)` → `[{chapter, nodes:[{x,y,...}], width}]` 与 `summarize(payload)`；
vitest 覆盖：空章、缺目标、多断点、节点 x 递增。

后端 `causal_service.build_map(session, project_id)`：纯投影，pytest 覆盖排序、断点判定、
只收未处理因果问题、`logic_checked` 三态。

## 4. 边界

| 情况 | 行为 |
|---|---|
| 项目没有卷章 | `chapters: []`，前端空态「还没有章节结构」 |
| 章内 1 场 | 正常画（无箭头），不算断点 |
| 场景卡三项全空 | 三个断点里只标 `missing_goal` + `missing_turn`（不重复） |
| 逻辑问题已处理（status ≠ open） | 不算断点、不进 issues |
| 从未跑过逻辑自检 | `logic_checked: false`，不显示因果问题类断点，顶部提示未检查 |
| 场景锁定 | 节点带锁标记，仍可点 |

## 5. 测试与走查

- pytest：`causal_service` 排序与断点；接口 404（项目不存在）。
- vitest：布局与计数。
- 走查：临时目录造 2 卷 4 章 10 场（含缺目标、缺转折、带因果问题的场景），截图核对；
  点节点能跳到结构设计并选中。

## 6. 明确不做

- 整本书的跨章因果图（先按章，够用再谈）。
- 设定投放曲线、性格漂移曲线（各自另立）。
- 在图上直接编辑场景卡（点进去改）。
