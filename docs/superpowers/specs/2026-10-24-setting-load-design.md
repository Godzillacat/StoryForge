# 逻辑自检 · 设定投放曲线 · 设计

> 二期第四项之二（D-22 三张辅助视图的第二张）。第一张因果链图已交付。
> 第三张性格漂移曲线需要**逐章人物状态历史**，是本张之后单独一段。

## 1. 意图

作者最常犯的长篇病不是「设定太少」，而是**一章里一次砸下二十个新名词**：读者记不住，
设定也没有推动情节。产品 §4.7 的「设定载荷」检查问的就是这个，但它只在**单场**里给问题；
作者需要的是**整章、整卷的投放节奏**：

- 哪一章新名词最多（读者认知负担的峰值）；
- 哪些章一个设定都没提（设定写了一大堆，正文里没用上）；
- 某个核心设定是第几章第一次出现的（是不是拖到太晚）。

**设定投放曲线**把这三件事画成一条按章排列的曲线，不调用模型、不判断「好不好」，
只把「投了多少」摆出来。

## 2. 目标 / 非目标

**目标**

1. 按卷 → 章统计：**新出现**的设定条目数、**总提及**次数、每千字提及密度。
2. 判定「新出现」：该条目（名字或别名）在**阅读顺序上第一次**出现在哪一章。
3. 点章 → 跳到写作台/结构设计并选中该章。
4. 顶部给全项目汇总：条目总数、已投放条目数、从未在正文出现的条目数。

**非目标**

- 不判断「投放太多 / 太少」—— 那是逻辑自检（LLM 层）的事；曲线只给事实。
- 不统计「读者是否理解」，不做语义消歧：**按字面命中**，与术语表同一套白名单。
- 不做跨项目、不缓存到库（每次现算）。

**反目标**

- 不能把「没写过正文的章」画成 0 —— 那是「还没写」，不是「没投放」；必须区分并灰显。
- 不能在同一个 form 对应多个条目时静默选一个而不记录 —— 数字会偏，且没人知道。

## 3. 方案

### 3.1 后端：一次扫描

`GET /api/projects/{id}/setting-load`

```json
{
  "chapters": [
    {"id": "...", "label": "第1章 雨夜", "volume_label": "第一卷",
     "has_body": true, "chars": 3200,
     "new_terms": [{"entry_id": "...", "name": "雾港", "form": "雾港"}],
     "new_count": 3, "mentions": 14, "density": 4.4}
  ],
  "totals": {"entries": 42, "delivered": 18, "never_seen": 24, "ambiguities": 2},
  "reason": ""
}
```

- **词表**：`SettingEntry.name` ∪ `aliases_json` 的每个 form（trim、去空、去重）；form → 条目
  取「名字等于 form」优先，否则取最早创建的条目；同一 form 命中多个条目时计入 `ambiguities`。
- **扫描**：把全部 form 按**长度降序**拼成一个正则（`re.escape`），对每个有正文的场景扫一遍；
  长 form 优先命中（「阿明哥」不会同时算成「阿明」）。
- **归属**：命中按场景所属章累加；`new_terms` 取该 form 在全项目阅读顺序里**第一次**出现的章。
- **密度**：`mentions / (chars/1000)`，`chars=0` 时为 0；`chars` 用既有 `count_words`。
- `has_body`：该章至少一场有已采纳正文；**没有正文的章不参与「从未出现」判定**。
- `never_seen`：词表里从未在任何正文出现的条目数。

### 3.2 前端：柱 + 线

位置：结构设计页视图区（与因果链、节奏曲线并列）。

```
设定投放   42 个条目 · 已投放 18 · 从未出现 24 · 2 处重名
┌ 柱：每章新设定数   线：每千字提及密度 ─────────────┐
│  ▁ ▃ ▅ ▂ █ ▁  …                                  │
└───────────────────────────────────────────────────┘
    第1章   第2章   第3章 …（点章跳转）
```

- 柱状 = `new_count`，折线 = `density`；**无正文的章**画灰色空位并标「未写」，不画 0 柱。
- 悬停给「新 3 / 提及 14 / 3200 字」。
- 点章 → 与因果链相同的跳转。

### 3.3 纯函数

`frontend/src/lib/settingLoad.ts`：`buildLoadSeries(data)` → `{chapters, maxNew, maxDensity}`；
vitest 覆盖空项目、无正文章、密度除零。

## 4. 边界

| 情况 | 行为 |
|---|---|
| 项目没有条目 | `chapters` 照常（全 0），`reason: "还没有设定条目"` |
| 条目没有名字也没有别名 | 跳过该条目 |
| 别名重复（A、B 都叫「老师」） | 计入 `ambiguities`，命中归「名字等于 form」或最早创建者 |
| 同一 form 在同一场出现多次 | `mentions` 计次数，`new_terms` 只在该章首次出现时列一次 |
| 章没有任何已采纳正文 | `has_body=false`，不参与新/旧判定，前端灰显 |
| 全部章都没正文 | 全灰 + `reason: "还没有已采纳正文"` |

## 5. 测试与走查

- pytest：词表构造与去重；长 form 优先；同场多次提及；首次出现归属；无正文章不算「从未出现」；
  重名计 `ambiguities`；密度除零；项目不存在 404。
- vitest：布局与空态。
- 走查：临时目录造 2 卷 4 章（其中一章无正文）+ 6 个条目（含一个核心设定第 3 章才出现），
  核对曲线与汇总；点章跳转。

## 6. 明确不做

- 语义消歧、代词指代、同一设定的同义表述合并（那需要模型或人工映射）。
- 把统计落库缓存（本机单用户，现算够快）。
- 性格漂移曲线（下一段，需要逐章人物状态历史）。
