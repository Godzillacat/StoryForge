# StoryForge 前端界面重塑 · 设计文档

- 日期：2026-10-25
- 状态：**已批准**（2026-10-25 作者确认）
- 范围：`frontend/` 全部 13 个页面 + 应用外壳；**后端零改动**（批次 0b 唯一例外：前端数据流，仍不碰后端）
- 决策方式：作者逐轮对答（形状 → 气质 → 字体 → 主色 → 导航 → 形态 → 排版 → 动效 → 密度 → 落地方式）

---

## 1. 意图与为什么

现在的界面不是"设计过的"，是 13 个页面各自用 Tailwind 默认值堆出来的：全站只有 4 行全局样式，`slate-` 出现约 1025 次，字号只有 12px（309 处）与 14px（290 处）两档，`text-base` 一次没用，`transition` 零处；圆角几乎全是默认 4px（裸 `rounded` 418 处，带尺寸的 `rounded-*` 仅 7 处），`shadow` 1 处。导航是 13 个等权条目平铺在 224px 侧栏里。

作者的原话是"为前端界面做优化"，逐轮对答后收敛为六条具体痛点：找不到功能、字小且没层级、卡片边界不清、表格与表单太密、写作台右栏挤到要"全屏展开"、操作像在刷静态页。

**这次要解决的不是"更好看"，是让一台每天要盯四小时的写作机器有稳定的视觉秩序**：一眼能分出"我在哪一层"，眼睛不用在 12px 里找东西，界面不抢稿子的注意力。

## 2. 目标

1. 建立一套**唯一的视觉语言**：令牌 + 组件 + 页面三层，页面不再各写一套类名。
2. 重新组织**信息架构**：13 个入口按创作阶段分组；写作台区分"工作态"与"专注态"。
3. 把**排版当成产品功能**：编辑区 17px / 行距 1.9 / 段间距，标题衬线、界面黑体；**首行缩进只出现在阅读器与 EPUB 传统模板**（编辑面是 Markdown 源码，缩进属于呈现层）。
4. 让**每个操作都有回应**：120–160ms 微过渡、骨架屏、轻提示，不再"点了没反应"。
5. 表格、表单、图表、空态在浅色底上重新校准，密度有明确标准（行高 44px）。

## 3. 非目标

- 不加任何新功能；不改任何业务逻辑、请求、状态机。
- 不做深色模式（作者明确选择单一浅色；夜间阅读仍由阅读器自己的主题承担）。
- 不引入 UI 组件库（shadcn / Radix / MUI 一律不引）、不引入图标库（手写 SVG）。
- 不做移动端/响应式断点：这是桌面应用，最小宽度按 1280px 设计。
- 不改后端、不改数据库、不改打包脚本。

## 4. 反目标（做到了也算失败）

- **把界面改成另一个产品**：作者打开的应该还是同一个 StoryForge，只是安静、清楚、有层次。
- **动画喧宾夺主**：任何过渡超过 200ms、任何元素持续闪烁，都算失败。
- **只换颜色不动结构**：那正是方案 B，作者已否掉。
- **破坏既有交互语义**：写作台的请求代际令牌、段落锁、采纳规则、面板互斥（生成中禁用审校等）必须原样保留，只换外观与栅格。
- **为好看降低可读性**：浅色底上的小字对比度低于 4.5:1 即失败（见 §6.2）。

## 5. 已定决策（作者拍板，不再讨论）

| 项 | 决定 |
|---|---|
| 底色 | 暖白纸感，浅色为主，**不做深色模式** |
| 气质 | 「暗房式克制」——光只打在稿子上，不靠阴影和大色块 |
| 字体 | 界面黑体（微软雅黑 UI / Segoe UI），标题与正文衬线（STSong → 宋体） |
| 主色 | 墨绿 `#2F5D4E`，只用于主操作、选中、光标、焦点 |
| 导航 | 按创作阶段分组（总览 / 构思 / 设定 / 写作 / 阅读与发行 / 系统） |
| 写作台 | 三栏为默认，另设「专注模式」（侧栏收成 56px 图标条、正文独占、面板浮动让位） |
| 正文排版 | 编辑区 17px / 行距 1.9 / 段间距、**不缩进**；缩进归阅读器与 EPUB |
| 表格密度 | 行高 44px |
| 动效 | 克制的微过渡（120–160ms）+ 骨架 + 轻提示 |
| 阅读器 | 「纸张」主题并入新语言；另两套主题保留 |
| 当前项目 | **由外壳统一持有**（顶栏选择器 + `localStorage`），页面不再各自选 |
| 写作台右栏 | 重组为四个页签：上下文 / 分支 / 审校 / 日志 |
| 仪表盘 | 删掉无数据源的「分卷进度」「本周每日字数」，KPI 全部改用 `report` 现有字段 |
| 落地方式 | **方案 C：令牌 + 组件层 + 布局重排**（作者选定） |

## 6. 设计语言

### 6.1 色彩令牌

| 令牌 | 值 | 用途 |
|---|---|---|
| `paper` | `#F4F1EA` | 页面底 |
| `surface` | `#FBF9F5` | 侧栏、工具栏、卡片、面板 |
| `sunken` | `#ECE7DC` | 输入框内衬、标签底、图表网格 |
| `ink` | `#23201C` | 正文标题与主要文字 |
| `ink-2` | `#4E4941` | 次级文字、表格正文 |
| `muted` | `#6E6A61` | 标签、说明文字（**不用于装饰线**） |
| `faint` | `#8D8679` | 仅装饰性：分隔点、占位符 |
| `line` | `#E3DDD0` | 1px 分隔线 |
| `line-strong` | `#CFC7B6` | 控件边框 |
| `accent` | `#2F5D4E` | 主按钮、选中、焦点、光标 |
| `accent-ink` | `#24483C` | 强调文字（选中态标题） |
| `accent-soft` | `#E6EFE9` | 选中底、焦点环 |
| `warn` | `#8A5C16` | 待处理、降级提示 |
| `warn-soft` | `#F6ECD8` | 提示底色 |
| `danger` | `#9B3B32` | 删除、失败 |

**对比度（已计算，浅色底 `#F4F1EA`）**：`ink` 14.5:1、`ink-2` 8.1:1、`muted` 4.8:1、`accent` 6.7:1、`warn` 4.6:1、`danger` 5.6:1。全部 ≥ 4.5:1，可用于小字。

> 注意：样板里用的 `#8D8679` 只有 3.2:1，**实现时必须换成 `muted` 的 `#6E6A61`**；`#8D8679` 只保留给"不承载信息"的装饰。

### 6.2 字体与字阶

```css
--sans: "Microsoft YaHei UI", "Segoe UI", system-ui, sans-serif;
--serif: "STSong", "Songti SC", SimSun, Georgia, serif;
```

| 角色 | 字号/行高 | 字体 | 字重 |
|---|---|---|---|
| 页面主标题 | 22 / 1.3 | serif | 600 |
| 区块标题 | 14 / 1.4 | sans | 600 |
| 导航项 | 13.5 / 1.4 | sans | 400（选中 600） |
| 正文（编辑区） | 17 / 1.9 | serif | 400 |
| 表格正文 | 13.5 / 1.5 | sans | 400 |
| 表单值 | 13.5 / 1.6 | sans | 400 |
| 说明文字 | 12 / 1.5 | sans | 400 |
| 组标签 / 表头 | 11 / 1.4，字距 .08em | sans | 500 |
| 大数字（KPI） | 28 / 1.2 | serif | 600 |

规则：**同一屏不超过四档字号**；字重只用 400 / 600 两档；不用全大写（中文无此概念），英文缩写可加字距。

### 6.3 间距、圆角、阴影

- 间距基数 4px；页面内边距 24，卡片内边距 16，区块间距 14/16，控件间距 8/10/12。
- 圆角：标签 4、控件 6、卡片 8、浮层 10。
- 阴影：**只有浮层有**——`0 10px 30px rgba(35,32,28,.10), 0 1px 2px rgba(35,32,28,.06)`；卡片一律 `1px solid line`，不加阴影。

### 6.4 动效

| 场景 | 时长 | 曲线 |
|---|---|---|
| 悬停/聚焦变色 | 120ms | ease-out |
| 面板开合、抽屉 | 160ms | cubic-bezier(.2,.7,.3,1) |
| 提示出现 | 150ms | ease-out |
| 骨架屏微光 | 1.6s 循环 | linear |

必须遵守 `prefers-reduced-motion: reduce`：全部降为 0ms，只保留状态变化。

### 6.5 焦点与悬停

- 焦点环：`0 0 0 3px accent-soft` + 边框 `accent`，**保证键盘可见**（现有 6 处 `focus-visible`，需覆盖到所有可交互元素）。
- 悬停：`surface → sunken` 一档差异，不改变尺寸、不位移。

## 7. 组件层（`src/ui/`）

| 组件 | 用途 | 关键约束 |
|---|---|---|
| `Button` | 主/次/幽灵/危险 四变体，`sm`(26)/`md`(32) 两尺寸 | 禁用态不改变布局宽度 |
| `IconButton` | 工具栏图标按钮 | 必须带 `aria-label` |
| `Field` / `Input` / `Textarea` / `Select` | 表单 | label 11.5px muted；聚焦态见 6.5 |
| `Card` | 内容容器 | 只有 1px 线，标题行右可放操作 |
| `Panel` | 左/右栏容器 | 可折叠；折叠后保留 44px 条 |
| `Tabs` | 页内切换 | 选中态用 sunken 底，不用下划线 |
| `Table` | 表格 | 行高 44，`th` 11px 字距，数字列右对齐 |
| `Badge` / `Tag` | 状态与类型 | 20px 高，4px 圆角，颜色只取自 §6.1 |
| `EmptyState` | 空态 | 一句话说明 + 一个主要动作 |
| `Dialog` | 确认框 | 遮罩 `rgba(35,32,28,.28)`，ESC 关闭 |
| `Toast` | 轻提示 | 右下角，3s 自动消失，不抢焦点 |
| `Skeleton` | 加载占位 | 只用于首次加载，不用于轮询 |
| `icons.tsx` | 约 15 个手写 SVG | 20×20，`stroke-width 1.5`，`currentColor` |

**不做**：不封装"业务组件"进 `ui/`；现有 `components/chapters|writing|reading` 保持原位，只替换内部标记。

- 侧栏 236px（可折叠到 56px 图标条），分组标签 11px / 字距 .12em，条目计数在右。
- 侧栏底部固定项目摘要（卷数、章节数、总字数），不随页面变化。
- 页面内容区不再统一 `p-6`：每页自己的工具栏负责横向内边距（20/24），阅读器仍完全自铺。

### 8.1 当前项目由外壳持有（作者已定）

**今天**：`App.tsx` 零 API 调用，13 个页面各自 `listProjects` 并各放一个 `<select>`；切项目时页面之间互不知道。

**改成**：外壳持有一个 `CurrentProject`（`projectId` + 名称），持久化在 `localStorage`（键与写作台的专注模式同一命名空间）；选择器放在**侧栏顶部（品牌下方）**，含项目下拉与「新建项目」入口；页面从 context 读取，删掉各自的 `<select>`。

> 位置说明：原稿写"顶栏"，施工时改为侧栏顶部——页面已经各有自己的工具栏，再加一条全局顶栏会形成"两层头"，在 900px 高的窗口里白吃 48px。选择器与项目摘要同处一侧，也符合"左边是书的目录、右边是稿纸"的心智。

- 数据：外壳只做两次请求——`/api/projects`（选择器）与 `/api/projects/{id}/entries`（侧栏设定条目计数）；底部摘要的卷/章/字数取自 `/api/projects/{id}/report`。全部按项目 id 缓存，切项目才重新取。
- **这是逻辑改动**，不是纯样式：13 个页面的初始加载路径与「无项目」「切项目」分支都会变。因此它单独成一批（§12 批次 0b），不混进视觉批次。
- 没有当前项目时（首次启动）：顶栏显示「选择或新建项目」，页面显示 `EmptyState`，不自动建项目。

### 8.2 宽度预算（写作台，1280 与 1440 必须算得开）

| 视口 | 外壳 | 左树 | 正文 | 右栏 | 形态 |
|---|---|---|---|---|---|
| ≥1440 | 236 | 236 | 弹性，目标 600–680（上限 680，余量变页边） | 336 | 三栏（默认） |
| 1280–1439 | 236 | 抽屉（浮层，点工具栏呼出） | 560–620 | 320（浮层） | **默认即专注态** |
| <1280 | 56 | 抽屉 | 弹性 | 浮层 | 不承诺；应用最小窗口按 1280 设计 |

验算：1440 − 236 − 236 − 336 − 32（两道 16px 间隙）= **600**，落在目标区间内；1280 − 236 − 560 = 484，由左右页边吸收，正文不压缩到 560 以下。

## 9. 逐页改造

> 每页只写"现状 → 新版"的**结构差异**；配色与字阶全站统一，不重复。

### 9.1 故事仪表盘（407 行，3 栅格）

现状：KPI 三列 + 体检单 + 导出 + 最近改动纵向堆叠。
新版：顶部一行标题 + 两个动作；KPI 四列，**全部用现有数据**——总字数（`report.total_words`）、已写场景（`scenes − scenes_without_body.length` / `scenes`）、未回收伏笔（`unrecovered_foreshadows.length`）、待处理问题（`open_audit_issues + open_logic_issues`），数字用衬线；下方两栏——左「体检单（未写场景 / 未回收 / 锁定 / 待复核）+ 最近改动」，右「导出与成品报告（封面 + 模板 + 三个下载）」+「版本与快照」。

> **删掉两处不存在的指标**（builder check 指出）：分卷进度条与"本周每日写作柱"在全仓没有数据源，`report` 只给总量、不给按卷或按日。不造数据、不为它加接口。若将来要，属于「统计」这一新功能，另立项。

### 9.2 灵感与解析（160 行，单列）

现状：一个长表单，灵感条目与解析卡上下堆叠；解析卡标题写着"可逐项编辑"，**实际是只读纯文本，后端也没有更新接口**（`api/ideas.py` 只有 `POST .../parse`）。
新版：左 300px 灵感条目列表（含时间与是否已解析），右侧解析卡**明确按只读展示**（标题改为「解析卡 · 只读」，逐字段用定义列表排版），作者原话固定展示且标注"AI 不会改这段"；顶部工具栏放「解析」与「存为灵感」。**原话区域用衬线、底色 sunken，与解析结果明确区分。** 想改解析结果，路径是重新解析，不是就地编辑——这一点在界面上直说，不留假入口。

### 9.3 架构推荐（425 行，3 栏）

现状：三套方案三个卡片并排，字段各自成段，难以横向比较。
新版：保留三栏并排（产品要求），但改成**同行同字段对齐**：适配度 / 篇幅分配 / 节奏形态 / 风险 / 不适用情形 各占一行，三列同高；顶部一条对比摘要（差异点由前端从字段里提）；故事圣经 v0 与「已写入的结构」下移为独立区块。

### 9.4 世界观（498 行，260px + 1fr）

现状：左列表 + 右编辑器，但编辑器字段是纵向长表单。
新版：列表加到 308px（类型标签定宽 + 提及数右对齐）；详情区标题行带状态标签与「影响面 / 标为待复核」；人物八项用两列栅格（长文本跨列）；别名/称呼做成 chip 行；关联条目单独一段。

### 9.5 关系网（356 行）

现状：关系列表 + 建立关系表单纵向排列。
新版：左 280px 人物筛选（含"只看人物↔人物"开关），中间关系表（A / 方向 / B / 强度 / 备注），右侧编辑面板；「同时建立反向」作为表单单选项，不做成第二个按钮。

### 9.6 时间线（286 行）

现状：事件列表 + 上下移动按钮。
新版：纵向时间轴（左侧竖线 + 节点），每个事件卡片显示 `story_time`、参与者 chip、地点；右侧编辑面板；上移/下移改为拖拽外的两个图标按钮（保持可键盘操作），并保留"按序号"的排序说明。

### 9.7 术语表（125 行）

现状：表格 + 类型筛选。
新版：工具栏（搜索 + 类型筛选 chips + 计数），表格三列（形式 / 类型 / 来源条目），同名冲突行用 `warn` 标记并在行内说明"两个条目共用这一称呼"。

### 9.8 章节设计（822 行，300px + 1fr，7 页签）

现状：左树 + 右内容，7 个页签横向平铺。
新版：页签收敛为「结构 / 节奏 / 伏笔 / 视图」四组，后三组合并为「视图」下的二级切换（因果链、设定投放、性格漂移、剧情线），避免 7 个页签在 1280px 下换行；场景表行高 44，选中行左侧 2px 墨绿；节奏图重画（墨绿实线 + 沙色虚线 + 更淡网格）；锁定状态用锁形图标 + `warn` 小标签，不用整行变色。

### 9.9 写作台（1532 行，240/1fr/320）

现状：三栏固定，右栏挤，需要全屏展开；正文是 `<textarea>`（`SceneTextView.tsx`，`rows=18`、`resize-y`、等宽字体），右栏是**一个 aside 里并排 11 个面板**（含 450 行的 A/B 面板与 427 行的分支面板）。

新版：

- **工作态（默认，≥1440）**：左树 236px、正文弹性 600–680、右栏 336px（可折叠为 44px 条）；顶部工具栏一行（面包屑、保存状态、对比草稿、采纳、生成正文、更多；项目选择器在侧栏顶部，不在这里）。

## 10. 状态与反馈规范

| 状态 | 表现 |
|---|---|
| 首次加载 | 骨架屏（与最终布局同尺寸），不用转圈 |

| 失败 | 行内错误条（danger 左边线 + 一句可读中文），必要时附"重试" |
| 空态 | EmptyState：一句说明 + 一个主操作；不出现"暂无数据"这种空话 |
| 锁定 | 锁形图标 + 悬浮说明"AI 不得改动；作者仍可编辑" |
| 降级（无模型等） | warn 提示条常驻，不伪装成成功 |

> **本轮刻意不动的两件**（builder check 提醒的冲突点）：
> 1. 全站 211 处 `setNotice` 的成功与失败共用同一个字符串。本轮只换外观（颜色、位置、停留时长），**不判定成败**；要分流转 Toast，得先让每处调用带上类型，那是逻辑改动，记后续。
> 2. 25 处 `window.confirm` 不替换成 `Dialog`。`Dialog` 组件仍建（批次 0a），但只服务新增确认入口；全面替换属于批次 5 之后的独立事项。

## 12. 分批与风险

| 批次 | 内容 | 独立可交付 |
|---|---|---|
| 0a 视觉地基 | 令牌、`src/ui/`、图标、外壳与导航（**纯样式**，数据流不动） | 是 |
| 0b 项目状态 | 外壳持有当前项目：context、顶栏选择器、13 页去掉各自的 `<select>`、侧栏计数与摘要 | 是（**唯一动数据流的一批**，单独提交、单独回归） |
| 1 高频 | 写作台、章节设计、世界观、仪表盘 | 是 |
| 2 设定 | 灵感、架构、关系网、时间线、术语表 | 是 |
| 3 系统与发行 | 工作室、模型与费用、管线、阅读器 | 是 |
| 4 收尾 | 动效、空态、错误态、键盘、对比度复核、截图归档 | 是 |

**主要风险与缓解**

1. **13 页标记重写、UI 无自动化测试** → 每批结束跑构建 + 无头截图 + 作者手点；单批不超过 4 页。
2. **改结构时误伤逻辑** → 硬规则：只动 JSX 结构与 `className`，不动 `useEffect` 依赖、请求顺序、令牌竞态、锁判定；每批 diff 里出现逻辑改动即回退（0b 批次是唯一例外，单独评审）。
3. **0b 批次会同时触及 13 页的加载路径** → 先做 0b 再做页面级改造，避免"边改样式边改数据流"；0b 单独一个提交，可整体 revert。
4. **衬线字体在无 STSong 的机器上退化** → 已确认本机有 STSong；退化到宋体可接受，不打包字体（避免 +10MB）。
5. **浅色底上图表失真** → 图表单独重画配色，不直接反色。
6. **阅读器自铺样式与外壳冲突** → 阅读器继续走"无内边距"路径，不改 `App.tsx` 的例外规则。

## 13. 留给 builder 的决定

- `src/ui/` 内部是否用 `clsx` 之类的拼接工具（**倾向不加依赖，手写模板字符串**）。
- 外壳的项目状态用 `Context + useReducer` 还是极薄的 `useSyncExternalStore` store（**倾向 Context**，13 页只需读）。
- 图表继续各页手写 SVG，还是抽一个 `Chart` 基础件（**倾向保留各页手写，只统一颜色常量**）。
- 页面级滚动容器归属：**倾向「外壳不滚、页内各自滚」**，与写作台现状一致。
- 旧样式残留（如 `index.css` 里除 `@tailwind` 与 body 之外的规则）是否清空重建（**倾向重建**）。
- 是否同时引入 `pnpm lint`（`oxlint` 已在 devDependencies）作为批次门禁（**倾向跑，但不阻塞合并**）。
