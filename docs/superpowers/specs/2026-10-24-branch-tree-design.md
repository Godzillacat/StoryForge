# 场景分支树 · 设计

> 二期第五项。**先松动了既定决策**：CLAUDE.md 2026-10-22 曾记「分支只有一层，不做分支树」；
> 产品文档 §9.1 本来就写「分支树能看清一部作品走过哪些岔路」。本次按 **A 方案** 落地：
> **分支可以从另一条分支派生（最多三层），派生关系画成树；采纳仍是整份替换正文，不做逐层合并。**

## 1. 意图

作者试写法时常见的动作是「在这一版的基础上再试一版」：先写一版「阿明犹豫」，
再想「如果他一开始就决意会怎样」—— 后一版是从前一版改出来的，不是从主版重新长出来的。

现在所有分支都平铺在同一层，作者看不出「谁从谁改出来」，也没法「基于这一版再派生」。
本段补两件事：

1. **派生**：从任意一条分支新建分支，新分支**复制父分支的正文**作为起点；
2. **树**：分支列表按派生关系缩进展示，一眼看出演化路径。

## 2. 目标 / 非目标

**目标**

1. `scene_branch` 加 `parent_branch_id`（可空）；迁移 **v13**（`ALTER TABLE ... ADD COLUMN`）。
2. 建分支接口接受可选 `parent_id`：校验同场景、非 A/B 临时分支、**深度 < 3**；新分支正文复制父分支正文。
3. 列表返回 `parent_id` 与 `depth`；前端按树缩进，并给每行一个「从这一版派生」。
4. 丢弃父分支时，子分支**提升为根**（`parent_id` 置空），不级联删除。
5. 采纳 / 合并语义**完全不变**：任何一条分支都直接替换主线正文。

**非目标**

- 不做逐层合并 / 三方合并 / 冲突解决。
- 不做图形化树（缩进列表就够；画图另算）。
- 不允许从 A/B 临时分支派生（它们采纳或丢弃后即删）。

**反目标**

- 不能因为父分支被丢弃就把子分支一起删掉 —— 子分支是作者写过的正文。
- 不能让深度无限增长 —— 三层以上缩进在小面板里已经读不清。

## 3. 方案

### 3.1 数据与迁移

`scene_branch.parent_branch_id TEXT NULL`，迁移 v13：

```sql
ALTER TABLE scene_branch ADD COLUMN parent_branch_id TEXT
```

不加外键：SQLite 的 `ALTER TABLE ADD COLUMN` 加 `REFERENCES` 有历史坑，
且「父分支被删 → 子分支提升为根」本来就是服务层语义，用外键 `SET NULL` 反而把行为藏进 DDL。

### 3.2 服务

- `create_branch(..., parent_id=None)`：
  - 父分支存在、同场景、`ab_group is None`；
  - 父深度 < 3（根 = 1 层，最深 3 层）；
  - 新分支 `content` 复制父分支 `content`（父没有正文就复制空串），`note` 记「派生自 …」；
  - 名字仍走 `_unique_name`。
- `serialize_branch` 增加 `parent_id`、`depth`；`depth` 由服务层沿父链算（一次取全场景分支，不逐条查库）。
- `discard_branch`：删除前把子分支的 `parent_id` 置空（`UPDATE ... WHERE parent_branch_id = :id`）。
- `ab_create` 不设父（A/B 对仍是根）。

### 3.3 前端

写作台分支列表：

```
分支
├ 阿明犹豫（主选）        [采用] [派生] …
│ ├ 阿明决意               [采用] [派生] …
│ │ └ 阿明决意（短版）      [采用] [派生] …
└ 第三人视角               [采用] [派生] …
```

- 缩进 = `(depth-1) × 16px`；父名显示为小字「派生自 阿明犹豫」；
- 「派生」按钮 → 提示输入新名字（默认「父名 · 派生」）→ 建分支 → 自动选中新分支；
- 深度到 3 时「派生」禁用并说明「最多三层」。

## 4. 边界

| 情况 | 行为 |
|---|---|
| 父分支不存在 / 别的场景 | 404 |
| 父分支是 A/B 临时分支 | 400「A/B 分支不能作为派生起点」 |
| 父深度已是 3 | 400「最多三层分支」 |
| 父分支没有正文 | 新分支空正文，正常 |
| 丢弃父分支 | 子分支提升为根，正文与草稿不动 |
| 采纳某条子分支 | 与现在一样：整份替换主线、进修订历史 |
| 旧库（无该列） | 迁移 v13 补列，默认 NULL（所有旧分支为根） |

## 5. 测试与走查

- pytest：迁移 v13 在存量库执行一次；`parent_id` 写入与读回；深 3 拒绝、深 2 允许；跨场景 404；A/B 父拒绝；父被丢弃后子为根；`depth` 计算（根=1，两层=2，三层=3）。
- vitest：树构建纯函数（`buildBranchTree` 排序与缩进、孤儿当根）。
- 走查：临时目录造 1 场景、三层分支，核对缩进与「派生自」；丢弃中间父分支，看子分支提升为根；采纳最深一条，正文与修订历史正确。

## 6. 明确不做 / 后续

- 逐层合并、三方合并、冲突解决（维持 2026-10-22 的另一半决定）。
- 分支树图形化。
- 从 A/B 临时分支派生。
