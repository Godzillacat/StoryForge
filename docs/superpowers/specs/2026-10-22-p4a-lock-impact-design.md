# StoryForge P4a 设计：锁定与影响面分析

> 2026-10-22。P4 的第一段。P2/P3 让 AI 能一路产出材料，但作者手里还缺两样东西：**AI 不许碰的地方**，和**改一处会牵动哪里**。这两件合起来才是 P4 的完成标志——「改上游不失控，改一处知道会牵动哪里」。
>
> 上位依据：`StoryForge-产品设计文档.md` §3.3（影响面分析）、§3.4（锁定与分支）、§4.8（导出前成品报告含锁定状态）、D-03（可编辑、可追溯、可回退、可锁定）、D-04（AI 不覆盖作者原文）。

## 1. 阶段定义

### 1.1 这一段要解决什么

**问题一：AI 会改到作者不想让它改的东西。** 今天的写路径里，任何一次「写入项目 / 写入本章」都可能整批替换卷章场景；「采纳」会用草稿整份覆盖正文；批量生成会给每个空场景写草稿。作者若对某几章已经满意、不想再动，**没有任何办法告诉系统「这些别碰」**。`architecture.locked` 这一列从 P1a 就在，但全仓没有一处读它——它是个摆设。

**问题二：改上游不知道代价。** 作者把主角动机从「为父报仇」改成「为妹妹赎罪」时，系统不会告诉他这一改牵动了 7 个已写的场景、2 条未回收伏笔。他只能靠记忆与翻页去查，查漏一次就是一个自相矛盾的长篇。

P4a 交付三件事：

1. **锁定**：架构、设定条目、卷、章、场景可锁；场景正文还可按**段落**锁。所有 AI 写路径遇到锁定内容时**拒绝或跳过**，并说清是哪一处。作者的手工编辑不受阻（方向盘在他手里），但界面会标出「AI 不会碰这里」。
2. **影响面分析**：改动上游前，列出下游受影响的对象、其中多少是锁定的，并允许一键把它们标为**待复核**。
3. **待复核标记**：被影响但作者还没重看的对象，在界面上有明确标记，可逐条或批量清掉；导出前报告里也如实统计。

### 1.2 验收标准

1. **锁定可设可查**
   - 架构、设定条目、卷、章、场景五类可锁；场景正文的段落可单独锁。
   - 锁定状态在接口与界面上可见；刷新后保持。
   - **有效锁定向上继承**：章被锁，其下所有场景都算锁定；卷被锁，其下所有章与场景都算锁定。
2. **锁定约束所有 AI 写路径**（每一条都要有测试，且错误信息说清是哪一处被锁）
   - 对锁定场景发起正文生成 → 直接拒绝，**不发起模型调用、不花钱**。
   - 对锁定场景采纳草稿 → 拒绝。
   - 批量生成 → 跳过锁定场景，任务里记下跳过数，其他场景照常跑。
   - 章纲写入（`replace`）会删掉锁定卷/章/场景 → 拒绝整次写入并列出被锁对象；`append` 不受影响。
   - 场景写入（`replace`）会删掉锁定场景 → 拒绝整次写入。
   - 架构采纳会重写幕骨架 → 架构已锁时拒绝。
   - 回写应用 → 跳过锁定的目标（章节摘要 / 人物状态 / 伏笔回收），其余照常应用，返回里列出跳过项。
   - **作者手工保存正文、编辑条目、删除对象不受锁限制** —— 锁只约束 AI。
3. **段落锁定**
   - 场景正文可按段落锁；展开为「段落的完整文本」保存（不做位置锚点，正文重排不影响判定）。
   - 采纳 AI 草稿时，若草稿里缺少任一已锁段落（逐字比对），**拒绝采纳**并列出缺失段落。
   - 作者手工保存时不阻断；若保存后已锁段落不在正文里，界面明确提示。
4. **影响面分析**
   - 给定上游对象（架构 / 设定条目 / 卷 / 章 / 场景），返回下游受影响对象的分组清单，每组带总数与其中锁定数。
   - 分析是**只读**的：调用它不改变任何数据。
   - 设定条目的影响面包含**正文里提到它的场景**（走已有的 FTS 检索）。
5. **待复核**
   - 可把影响面里的下游对象一键标为「待复核」；标记按（项目, 对象类型, 对象 id）唯一，重复标记幂等。
   - 可逐条或批量清除；界面在章节树 / 世界观页有可见标记。
   - 导出前成品报告新增「锁定状态」与「待复核数」两项。
6. **基线**：后端既有 717 条全绿；前端 30 条全绿、`pnpm build` 干净。
7. **真实模型复验**：本段的行为全部是确定性的，**不调用模型**；用临时数据目录走查锁定拦截与影响面清单。

### 1.3 明确不做（并说明去向）

- **「生成修订建议逐条确认」**（§3.3 的第二个选项）—— 它是一条新的 AI 执行路径（为每个受影响对象生成一条改写建议、逐条确认），需要自己的提示词、契约与真实模型验证。P4a 只交付**分析**与**待复核标记**这两步，把「建议」记为后续项。作者今天的替代路径是：看到影响面 → 自己去改 → 清掉待复核标记。
- **场景级分支**（§3.4 后半）—— 属 P4b。
- **项目快照与回滚**（§4.11）—— 属 P4b。
- **伏笔账本闭环**（生命周期状态、回收率）—— 属 P4c。
- **逻辑自检图形化视图** —— 依 D-22 推到二期，P4c 只做逻辑链文本视图。
- **锁定段落的高亮渲染** —— 正文编辑仍是 Markdown 源码框；锁定段落以清单形式管理，不做富文本内联标记。
- **影响面的自动传播**（改了架构就自动改写下游）—— 违反 D-03：AI 产出必须先落在编辑区。

## 2. 已定决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 锁的语义边界 | **只约束 AI 写路径**；作者手工操作永远可行 | 产品原话是「锁定的内容 AI 不得改动」。把手工作者也锁死，会让作者为了改一个字先去解锁，是拿控制力换摩擦 |
| 锁的继承 | 向**下**继承：卷 → 章 → 场景 | 作者想保护的是「这一卷别动了」，逐个场景去点不现实；继承规则单一，不会有歧义 |
| 段落锁的标识 | 存**段落完整文本**，不存行号或偏移 | Markdown 编辑会让偏移立刻失效；逐字文本在「正文重排」下仍成立，代价是改一个字就等于换了一段（这本来就是作者想表达的） |
| 段落锁的强制执行点 | 只在**采纳 AI 草稿**时拒绝 | 草稿是 AI 的产物，采纳是它进入稿件的唯一入口。在生成时拒绝没有意义（草稿本来可以改） |
| 新列还是新表 | `locked` 用**显式列**（4 张表各一列）；段落锁是 `scene.locked_paragraphs_json`；待复核用**新表** `review_mark` | 锁定是每张表自己的属性、要能按它筛；待复核是跨实体的同一种标记，一张表比六张表各加两列干净 |
| 影响面是预览还是落库 | **只读预览**，不改任何数据 | §3.3 的「交给作者定夺」要求先看到代价再决定；副作用发生在作者点「标为待复核」时 |
| 「待复核」如何清除 | **显式操作**，不随编辑自动清除 | 「改过了」与「看过了、决定不改」都该能清掉标记；自动清除会让「还没看」与「看过不改」无法区分 |
| 迁移 | 新增 **v8**，四条 `ALTER TABLE ... ADD COLUMN locked` + 一条 `locked_paragraphs_json`，全部有服务器默认值 | 迁移只改已有表；新表 `review_mark` 走 `create_all` |

## 3. 数据

### 3.1 新增列（迁移 v8）

`requires=("setting_entry", "volume", "chapter", "scene")` —— 五条语句分属四张表，**必须四张全在才执行**；只缺一部分时 runner 会拒绝启动（既有语义，正合用：迁移只为存量库服务，全新库由 `create_all` 直接建出带列的形态）。

|---|---|---|---|
| `setting_entry` | `locked` | BOOLEAN | `0` |
| `volume` | `locked` | BOOLEAN | `0` |
| `chapter` | `locked` | BOOLEAN | `0` |
| `scene` | `locked` | BOOLEAN | `0` |
| `scene` | `locked_paragraphs_json` | JSON | `'[]'` |

`architecture.locked` 已存在（P1a 建的），本段开始真正使用。

### 3.2 新表 `review_mark`

| 列 | 类型 | 说明 |
|---|---|---|
| id | str(36) | |
| project_id | FK project CASCADE，索引 | |
| target_type | str(20) | `architecture` / `entry` / `volume` / `chapter` / `scene` |

## 4. 服务设计

### 4.1 `lock_service.py`

```
effective_scene_lock(session, scene) -> LockState
LockState = {locked: bool, source: "scene"|"chapter"|"volume"|None}
```
先看场景自己的 `locked`，再看章，再看卷。

```
set_locked(session, target_type, target_id, locked) -> dict   # 统一设置入口
get_locked(session, target_type, target_id) -> dict
paragraph_locks(session, scene_id) -> list[str]
set_paragraph_locks(session, scene_id, texts: list[str]) -> list[str]
missing_locks(content, locks) -> list[str]                     # 逐字比对，返回缺失项
```

`missing_locks` 是纯函数：按空行切段、`strip` 后逐字比较。**不归一化标点、不忽略空白** —— 段落锁的全部意义就是「一字不改」。

### 4.2 `impact_service.py`

```
analyze(session, project_id, target_type, target_id) -> dict
```

返回结构：

```json
{
  "target": {"type": "entry", "id": "…", "name": "沈砚", "locked": false},
  "groups": [
    {"key": "scenes", "label": "出场场景", "total": 7, "locked": 3,
     "items": [{"type": "scene", "id": "…", "label": "第1卷第2章 场景3",
                "locked": true, "path": "/chapters?project=…&scene=…"}]}
  ],
  "totals": {"all": 9, "locked": 3}
}
```

各目标类型的下游关系：

| 目标 | 分组 |
|---|---|
| architecture | 幕骨架（act 数）、卷（`act_seq` 落在骨架里的）、章、场景（含已写数）、未回收伏笔 |
| entry | 出场场景（人物）/ 使用该地点的场景（地点）/ **正文提到它的场景**（FTS，所有类型）、相关关系边、时间线事件、指向它的未处理审计问题 |
| volume | 章、场景（含已写数）、伏笔（埋设或计划回收在本卷内） |
| chapter | 场景（含已写数）、伏笔、未处理审计/逻辑问题 |
| scene | 伏笔（埋设/计划回收）、未处理问题、草稿与修订数 |

`locked` 的计算对 scene 走 `effective_scene_lock`，对 chapter/volume 是自己或祖先，对 entry 是自己的列。

### 4.3 强制执行点

| 位置 | 行为 |
|---|---|
| `text_service.prepare_generation` | 有效锁定 → `ValueError("这一场已锁定……")`，**在准备阶段就拒绝**（此时还没有运行记录、没有花钱） |
| `text_service.adopt_draft` | 有效锁定 → 拒绝；段落锁缺失 → 拒绝并列出 |
| `batch_service._available` | 跳过有效锁定的场景；`BatchJob` 记录跳过数（从 `scene_ids_json` 与可跑集合之差得出，不新增列） |
| `chapter_plan_service.write_chapter_plan`（replace） | 收集将被删除的卷/章/场景中锁定的对象，非空则整次拒绝 |
| `scene_service.write_scenes`（replace） | 同上，范围是本章 |
| `architecture_service.adopt` | `architecture.locked` 为真 → 拒绝 |
| `writeback_service.apply` | 锁定的章节 / 人物条目跳过，返回 `skipped` 列表；全部被跳过时不算错误 |
| `text_service.save_body` / `restore_revision` / 世界与章节的 CRUD | **不拦截** |

### 4.4 待复核

```
add_marks(session, project_id, items) -> int     # 幂等，返回新增数
list_marks(session, project_id) -> list[dict]
clear_mark(session, mark_id)
clear_marks(session, project_id, items)          # 批量
```

对象被删除时清理标记：在 `delete_entry` / `delete_volume` / `delete_chapter` / `delete_scene` 里顺手删；架构采纳时不动标记（同一行被原地更新）。

## 5. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| PATCH | `/api/locks/{target_type}/{target_id}` | `{locked: bool}`，五类目标统一入口 |
| PUT | `/api/scenes/{scene_id}/paragraph-locks` | `{paragraphs: [str]}`，覆盖式设置 |
| GET | `/api/projects/{project_id}/impact` | 查询参数 `target_type` / `target_id` |
| GET | `/api/projects/{project_id}/review-marks` | |
| POST | `/api/projects/{project_id}/review-marks` | `{items: [{target_type, target_id, reason}]}`，幂等 |
| DELETE | `/api/review-marks/{mark_id}` | |
| POST | `/api/projects/{project_id}/review-marks/clear` | `{items: […]}` 批量清除 |

错误码沿用既有约定：目标不存在 → 404；类型非法 → 400；被锁拦截 → 409（与「进行中的运行」同一种语义：当前状态不允许这个操作）。

## 6. 前端

- **锁定开关**：章节页（卷/章/场景）、世界观页（条目）、架构页（故事圣经）。锁定时图标变实心、行首有标记；解锁需二次确认（避免误点）。
- **写作台**：场景锁定横幅（「这一场已锁定，AI 不会写它」），生成/采纳按钮禁用并说明原因；右栏新增「锁定段落」面板，列出当前正文段落并逐段开关；采纳被拒时把缺失段落列出来。
- **影响面**：架构、条目、卷、章、场景的编辑区各有一个「看看会影响什么」按钮，展开清单；清单顶部三个选项——「只改上层，下游标为待复核」/「取消」，第二个选项（生成修订建议）**显示为不可用并注明「后续提供」**，不假装能用。
- **待复核标记**：章节树与世界观列表上显示角标与原因；点击可清除；页面顶部有「N 条待复核」的筛选入口。
- **导出报告**：新增「锁定对象数」「待复核数」。

## 7. 测试策略

| 层 | 内容 |
|---|---|
| 迁移 | v8 在存量库形状上执行：五列齐全、旧行拿到默认值；全新库直接建出带列形态、不跑 v8 |
| 纯函数 | `missing_locks`（完全一致 / 少一段 / 改一字 / 顺序变化）；有效锁定继承 |
| 服务 | 每个强制执行点各一条「锁定 → 拒绝/跳过」+ 一条「未锁 → 照常」的对照测试 |
| 影响面 | 五种目标各一条；锁定计数正确；FTS 命中正文；未知目标 404；**调用前后数据不变** |
| 待复核 | 幂等新增、批量清除、对象删除后标记消失 |
| 接口 | 七条路由的状态码与载荷；409 的文案含被锁对象 |
| 前端 | 只做 build 与手工走查（项目约定：UI 不写自动化测试） |

## 8. 风险

- **锁定过度会挡住作者自己**：手工路径一律不拦，只有 AI 路径拦；采纳时若作者刚改过草稿又忘了锁定段落，拒绝是正确行为，但文案必须说清「哪几段不在」。
- **`replace` 写入被拒后的替代路径**：错误信息要给出「先解锁，或改用追加」。
- **影响面用 FTS 找「提到它的场景」**：检索索引是惰性重建的，刚写的内容可能还没进索引。这是既有检索语义，影响面里如实标注「按全文检索，可能有延迟」。
