# 逻辑链图形化 · 设计

> 二期第一项。对应产品设计文档 §4.7 第 202 行与 **D-22**：一期只出问题清单与逻辑链**文本**视图，
> 图形化属二期。本次只做**逻辑链**的图形，不做逻辑自检的三张视图（那是后一项）。

## 1. 意图

作者（一个人、深夜、一到四小时）写完一场戏后，想知道的是「这场戏的因果 / 转折 / 揭示**分布**得对不对」：
转折是不是全堆在结尾、中段是不是一路平推、某一类连接词是不是一次都没用。

现在的文本列表回答不了这个：它按顺序罗列，作者得自己在脑子里数。图形化要回答的只有一句 ——
**「这一场的力量分布长什么样」**。

## 2. 目标 / 非目标

**目标**

1. 用一个**派生视图**把 `GET /api/scenes/{id}/logic-chain` 已有的数据画出来，不新增数据、不改规则、不调用模型。
2. 横轴是**段落**（非空段落，与规则里的编号同一口径），一眼看得见空段与聚集。
3. 文本视图**保留**，一键切换；两者共用同一次请求，切换不发新请求。

**非目标**

- 不做跨场景 / 整章 / 整卷的逻辑链图（数据只有单场正文，跨场要先有语义关联，那是另一件事）。
- 不做节点点击跳转到正文对应段落（正文在另一个面板，滚动定位要引入引用机制，本项不做）。
- 不引入任何图表库或图形引擎（沿用 P1c-2 的「手写 SVG」先例）。

**反目标**

- **不能**把它画成「问题图」。链是「正文里写了什么」，问题是「哪里讲不通」；把两者画进一张图会让作者以为每个节点都有问题。
- **不能**让边暗示指代关系。规则不做指代消解，它不知道「因为」承接的是哪一句。

## 3. 已定方案

**段落轨道 + 顺序边（用户选定）。**

- 横轴：段落 1…N，每段一列；列内按出现顺序自上而下排节点。
- 节点：圆角矩形，宽度固定，两行截断，`<title>` 里放全文、连接词与段落号。
- 边：把相邻两个命中句连起来的折线 / 曲线，颜色取**后一个节点**的类型色。
- 空段：列仍在，只有段落刻度，没有节点 —— 这就是「第 2 段一条都没有」的信号。

### 考虑过但落选的

| 方案 | 为什么落选 |
|---|---|
| 横向流程条（一行排开） | 看不出段内密度与跨段跨度，正是本项要回答的问题 |
| 只做段落密度条 | 只有计数，没有句子，称不上「链」；作者还得回文本里找是哪句 |
| 力导向 / 自动布局 | 位置不稳定，同一份正文两次打开长得不一样；且没必要，顺序是已知的 |

## 4. 数据

### 4.1 后端：只补一个字段

`GET /api/scenes/{id}/logic-chain` 的响应加 `paragraphs: int` —— 正文的**非空段落数**。

理由：轴要覆盖整段正文。只靠命中句的 `paragraph` 推，只能画到**最后一个命中句**所在段，
后面的段落全被截掉，「结尾三段一条都没有」这个信号就没了。

口径必须与 `extract_chain` 完全一致（同一个分段函数），否则轴上的 ¶ 号会与列表里的 ¶ 号对不上。
实现：在 `logic_chain.py` 里加 `count_paragraphs(text) -> int`，两处共用 `_PARA_SPLIT`。

空正文 → `paragraphs: 0`；有正文但零命中 → `paragraphs > 0`，`chain` 为空（空态文案不变）。

### 4.2 前端：布局是纯函数

新增 `frontend/src/lib/logicChainGraph.ts`：

```
buildLogicChainGraph(chain: LogicChainItem[], paragraphs: number) -> {
  columns: { paragraph: number; nodes: GraphNode[] }[]
  edges:    { fromIndex: number; toIndex: number; kind: string }[]
  width: number
  height: number
}
```

- `columns` 长度 = `max(paragraphs, 最后命中段)`，保证轴覆盖正文；空段 `nodes: []`。
- 节点尺寸、列宽、间距是模块常量，测试直接引用，不写魔法数。
- 边按 `chain` 的下标连（i → i+1），`fromIndex` / `toIndex` 是**扁平的节点下标**，不是段落下标。

纯函数之外的东西（颜色、SVG 元素、toggle）留在组件里 —— 与 `chapterViews.ts` / `RhythmCurve.tsx` 的分工一致。

## 5. 界面

位置：写作台右栏 `LogicChain` 面板（`Writing.tsx` 第 1379 行挂载处不动）。

```
逻辑链   因果 5 · 转折 2 · 揭示 1            [图形 | 文本]
从正文里按连接词抽出，不做判断。问题清单在下面。
按出现顺序相连，不代表句子真的指向哪一句。      ← 只在图形模式显示

┌ 段落轨道（横向可滚动） ─────────────────────┐
│ ¶1        ¶2        ¶3        ¶4          │
│ ┌──────┐            ┌──────┐              │
│ │因为… │            │但是… │              │
│ └──────┘            └──────┘              │
│            （¶2 无节点，列仍在）            │
└───────────────────────────────────────────┘
```

- 默认进**图形**模式（这是本项要交付的东西）；点「文本」回到原列表，行为与现在完全一致。
- 空态沿用现有文案（`reason`），不画空图。
- 图形容器 `overflow-x-auto`，与 `RhythmCurve` 同一处理；高度随最多的那一列增长。
- 节点颜色取 sky / amber / emerald 的深色带值，**实施时必须核对深色底（`#020617`）上的对比度 ≥ 3:1**，
  并把实测值写进注释（沿用 `RhythmCurve.tsx` 第 12–14 行的做法）。

## 6. 边界

| 情况 | 行为 |
|---|---|
| 无正文 / 零命中 | 不渲染图，显示 `reason` |
| 只有 1 个节点 | 无连线，正常显示 |
| 一段里 10 个命中 | 该列变高，整图高度跟随；不折叠、不省略 |
| `paragraphs` 小于最后一个命中段（数据不一致） | 以命中段为准（`max`），不信任单个字段 |
| 正文里 ¶ 号跳号 | 空列照画，这就是信号，不压缩 |

## 7. 测试

| 层 | 内容 |
|---|---|
| pytest | `count_paragraphs` 的定义；API 返回 `paragraphs`（空正文 0 / 有正文无命中 > 0 / 与 `extract_chain` 同口径） |
| vitest | `buildLogicChainGraph`：列数、空段保留、列内顺序、边序列、单节点无边、`paragraphs` 偏小时取 `max` |
| 走查 | 真实浏览器：有正文的场景切图形/文本、悬停看全文、空场景看空态；切换不触发新请求（Network 面板） |

UI 本身不写自动化测试（项目约定）。
