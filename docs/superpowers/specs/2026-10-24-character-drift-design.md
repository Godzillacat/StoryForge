# 逻辑自检 · 性格漂移曲线 · 设计

> 二期第四项之三（D-22 三张辅助视图的最后一张）。前两张（因果链图、设定投放曲线）已交付。
> 与前两张不同：**这张需要新数据** —— 现在人物只有「当前状态」一个字段，没有逐章历史。

## 1. 意图

长篇里人物最容易出的问题不是「性格写得不对」，而是**性格变了却没交代**：
第 3 章怕水的人，第 9 章突然下水救人；或者相反 —— 作者铺了五章的转变，
读者却没感觉到变化。

产品要作者能一眼看到：**每个主要人物在第几章变过、变成什么样、中间隔了多久没变**。
这需要每条记录是「某章、某人、当时的状态」，而不是只存一个「当前状态」。

**本张先做手记版**：作者在章上给主要人物留一行状态（可只对关键人物、关键章记录），
曲线按人物画出「变 / 没变」。**不做模型抽取**（那是后续「自动填充」，见 §6）。

## 2. 目标 / 非目标

**目标**

1. 新表 `character_state`：`(chapter_id, entry_id)` 唯一，存 `note`（一行状态）与时间戳。
2. 接口：读整本（按人物分组的章节状态序列 + 变化次数）、单条写入 / 删除。
3. 视图「性格漂移」：每人一行、按章排列；**记录过且与上一次不同**的格子标为「变了」，
   相同标灰，没记录留空；悬停看全文；点格子可改。
4. 顶部汇总：记录了几人、几处变化、哪些人物只有一条记录（看不出漂移）。

**非目标**

- 不调用模型、不做语义判断（「这个变化合不合理」是逻辑自检的事）。
- 不做全自动逐章抽取（后续 C 方案，见 §6）。
- 不在本张里改人物「当前状态」字段（两者独立：`current_state` 是此刻，`character_state` 是历史）。

**反目标**

- 不能把「没记录」画成「没变化」—— 没记录是空白，不是 0。
- 不能把「与上一条记录相同」当成「没变化」而不显示 —— 它仍是作者确认过的状态，只是没变。

## 3. 方案

### 3.1 数据

新表 `character_state`（新表归 `create_all`，不需要迁移）：

| 列 | 说明 |
|---|---|
| `id` | UUID 主键 |
| `chapter_id` | FK → chapter，级联删除 |
| `entry_id` | FK → setting_entry，级联删除 |
| `note` | 一行状态（非空，≤500 字） |
| `created_at` / `updated_at` | 时间戳 |

唯一约束 `(chapter_id, entry_id)`；写入是 upsert。

### 3.2 接口

```
GET    /api/projects/{id}/character-drift
PUT    /api/chapters/{chapter_id}/character-states/{entry_id}   {"note": "..."}
DELETE /api/chapters/{chapter_id}/character-states/{entry_id}
```

返回：

```json
{
  "characters": [
    {"entry_id": "...", "name": "阿明",
     "cells": [{"chapter_id": "...", "label": "第2章", "note": "犹豫", "changed": false},
               {"chapter_id": "...", "label": "第4章", "note": "决意", "changed": true}],
     "changes": 1, "recorded": 2}
  ],
  "chapters": [{"id": "...", "label": "第1章 雨夜"}],
  "totals": {"characters": 3, "changes": 4, "sparse": 1},
  "reason": ""
}
```

- 只列**有记录的人物**；`cells` 只含有记录的章（前端按 `chapters` 对齐列）。
- `changed`：与该人物**上一条**记录比较（不是与上一章）；首条恒 `false`。
- `sparse`：只有一条记录的人物数（看不出漂移）。
- `reason`：项目无人物 / 无记录时的说明。

### 3.3 视图

结构设计页第四个视图「性格漂移」：表格式 —— 列是章、行是人物，格子是状态；
变化格琥珀底、相同格灰、空留白；点格子弹小输入框（预填现值）保存或删除。

### 3.4 纯函数

`frontend/src/lib/characterDrift.ts`：`buildDriftGrid(data)` → `{chapters, rows:[{entryId,name,cells,changes}]}`
（按 `chapters` 对齐，缺格填空）；vitest 覆盖对齐、空数据、sparse 计数。

## 4. 边界

| 情况 | 行为 |
|---|---|
| 项目没有人物条目 | `characters: []`，`reason: "还没有人物"` |
| 人物不是 `character` 类型 | 写入 400「只能记录人物的状态」 |
| 章不属于该项目 / 条目不属于项目 | 404 |
| note 为空 | 400「状态不能为空」 |
| 同一章同一人重复写 | upsert，更新 `updated_at` |
| 删除不存在的记录 | 404 |

## 5. 测试与走查

- pytest：upsert、唯一约束、变化判定（首条不算变）、稀疏计数、非法条目/章、note 校验、删除。
- vitest：网格对齐与空态。
- 走查：临时目录造 2 人物、4 章，给 A 记 3 条（其中 1 条与上条相同）、B 记 1 条；核对
  `changes` 与 `sparse`；截图核对格子样式；改一条后回读。

## 6. 明确不做 / 后续

- **自动抽取（C 方案）**：后续可加「按章读正文，模型提人物状态，作者确认后写入本表」——
  本表就是它的落地载体，不需要改结构。
- 状态的多字段化（欲望 / 恐惧 / 能力各一行）：现在一行自由文本，够用再拆。
- 性格漂移的**合理性**判断：属逻辑自检，不在这里。
