# A/B 并排生成 · 设计

> 二期第三项，对应产品 §5.6 与 **D-18**：「一期只做单版生成，多版并排选优放二期」。
> 本项做**写作台**的 A/B：同一场戏生成两版正文，并排看，采纳一版。**不做**智能体工作室的
> 「两个角色卡版本并排跑」—— 那是调试台的事，另记。

## 1. 意图

作者对某一场没把握时（「这个转折不确定，A 方案和 B 方案都写两章看看」—— 产品 §3.4 原话），
现在的做法是生成一次、不满意再点一次，**上一版被覆盖、也没法对照**。作者真正要的是：
两版同时在眼前，看清差异再选。

## 2. 目标 / 非目标

**目标**

1. 一场戏一键生成 **两版**，两版**同时**留在界面上，并排看。
2. 每版显示字数与「与另一版的差异段落数」；点「用这一版」→ 写进正文并记修订历史，另一版丢弃。
3. 两版都**不碰正文**，直到作者点「用这一版」。
4. 生成与采纳都遵守既有的锁：场景锁、卷/章继承锁、段落锁。

**非目标**

- 不做 A/B 的自动评分或「推荐哪版」—— 选择权是作者的。
- 不做三版以上、不做跨场景、不做两版合并。
- 不做工作室里的「角色卡 A/B」。

**反目标**

- 不能把两版都塞进 `scene_draft`（每场至多一条），也不能让 A/B 产生的临时数据长期堆在分支列表里。

## 3. 方案

### 3.1 选型：复用分支，还是新建临时表

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A. 复用 `scene_branch`（选定）** | 一次 A/B = 两条带 `ab_group` 标记的分支；生成走现成的 `/branches/{id}/generate`；采纳 = adopt + merge；用完删两条 | 零重复的流式生成代码、锁与段落锁天然一致；代价是要加一列标记，且分支列表必须过滤掉它们 |
| B. 新建 `scene_variant` 临时表 | 生成结果直接落新表，采纳时写正文 | 语义最干净；但要把流式生成、用量记账、锁检查在分支之外再实现一遍 —— 一份要长期维护的第二条生成路径 |
| C. 只在前端并排两次单版生成 | 连续两次 `/generate`，把结果留在组件里 | 第二次会覆盖第一次的草稿；刷新即丢；采纳要走一条没有修订记录的新路 |

选 A 的理由就是「不要再写一份生成链路」：P2a 的流式生成、P4a 的锁拦截、P4b-2 的分支修订都在
那条路上，复制一份必然漂移。B 的语义优势靠「用完即删 + 列表过滤」补。

### 3.2 数据

迁移 **v12**：`scene_branch` 加可空 `ab_group`（文本，同一次 A/B 的两条分支共用一个 uuid）。
新列走迁移（`requires=("scene_branch",)`），语句冻结为字面量。

- 分支列表 `GET /scenes/{id}/branches` **过滤 `ab_group is not null`** —— A/B 是实验，不是作者
  要长期保留的岔路。
- A/B 分支仍走 `create_all` 已有的表结构，除这一列外无变化。

### 3.3 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/scenes/{id}/ab` | 建两条 A/B 分支（`ab_group` 同值，名字 `A` / `B`，重名自动加序号），返回 `{group, branches:[{id,label}]}`；场景锁定时 409 |
| POST | `/api/scenes/{id}/ab/{branch_id}/adopt` | 采纳这一版：校验分支属于本次 A/B 且属于该场景 → adopt 草稿（段落锁）→ merge 到正文（场景锁）→ 删除同组两条分支；返回 `{revision_id, discarded:[...]}` |
| POST | `/api/scenes/{id}/ab/{branch_id}/discard` | 丢弃一版：删该分支；同组只剩一条时把它也删掉（A/B 结束） |

生成不新增接口：前端对每条分支调既有的 `POST /api/branches/{id}/generate`（SSE），**先 A 后 B 顺序跑**。
理由：SQLite 单写者，两条流同时写库会互相等；顺序跑至少失败时能说清哪一版没出来。

### 3.4 采纳的语义

1. `adopt_branch_draft`：把分支草稿变成分支正文（段落锁在这里生效，缺段拒绝）。
2. `merge_branch`：分支正文 → `scene.body`，旧主版进修订（来源 `branch`），**记一条改动历史**。
3. 删除同组两条分支（A 已合入正文、B 是落选方案）。

三步在**一个事务**里做；任何一步失败整体回滚，界面显示原因，分支保留可重试。
**不新增「A/B 采纳」的修订来源** —— 沿用 `branch`，作者在修订历史里看到的就是「从分支合入」。

### 3.5 界面

写作台右栏加「A/B 并排」入口（与「生成正文」并列，仅有已采纳正文或场景卡时可用）：

```
[A/B 并排生成]   →  生成中 A… / B…
┌──────────────┬──────────────┐
│ A · 1,240 字  │ B · 1,180 字  │
│ 差异 6 段     │ 差异 6 段     │
│ …正文预览…    │ …正文预览…    │
│ [用这一版]    │ [用这一版]    │
└──────────────┴──────────────┘
[两版都不要]
```

- 两版都从同一个场景卡与同一份上下文生成（同一智能体、同一参数）；**不提供**两版各绑不同模型
  （那是「模型对比」，需要另一套选择器，本项不做）。
- 差异段落数用现有的 diff 工具算（A 对 B），预览只读、可滚动。
- 采纳后两版都从界面消失；「两版都不要」= 丢弃两条分支，正文不动。
- 锁定的场景：入口禁用并说明「这一场已锁定」。

## 4. 边界

| 情况 | 行为 |
|---|---|
| 场景锁定（含卷/章继承） | 建 A/B 时 409；生成被既有拦截挡住；采纳再查一次 |
| 段落锁 | 采纳时缺段拒绝（沿用 adopt 的检查），B 不受影响 |
| A 生成成功、B 失败 | 界面保留 A，B 显示失败原因；可单独重试 B，或只用 A / 都不要 |
| 已有一组 A/B 未处理时再点 | 先丢弃旧的一组（界面确认），或禁用按钮直到处理完 |
| 刷新页面 | A/B 中间态丢失，两条分支留在库里但被列表过滤 —— 下次进入提示「有未完成的 A/B」并给「继续/丢弃」 |
| 采纳时分支已被删 | 404，界面提示重新生成 |
| 两版完全相同 | 正常显示，差异 0 段，作者随便选一版（不特殊处理） |

## 5. 测试

| 层 | 内容 |
|---|---|
| pytest | 建 A/B（锁 409、命名冲突加序号、列表过滤）；采纳（adopt+merge+删两条、修订来源 branch、改动历史 1 条、事务性：merge 失败时草稿不丢）；丢弃（删一条/删同组）；跨场景 branch_id 拒绝 |
| vitest | 差异统计纯函数（相同/不同段数、空文本） |
| 走查 | 真实模型生成两版 → 并排 → 采纳一版 → 正文与修订历史正确、另一版消失；锁定场景入口禁用 |

## 6. 明确不做

- 工作室的「两个角色卡版本并排」（另一项）。
- 两版各绑不同模型 / 参数。
- 三版以上、跨场景并排、两版逐段合并。
