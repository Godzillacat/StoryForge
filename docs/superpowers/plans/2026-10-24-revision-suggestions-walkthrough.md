|---|---|---|

## 证据

**1. 预置与绑定**

启动时播种出第 10 张卡「修订建议师」（`revision-advisor` / `revision_suggest`），初始 `model_binding_json` 为空；
用产品自己的版本接口新建 v2 绑定 `qwen3.8-flash`（v1 保留可回退）。

**2. 造的复验数据**（副本里）

- 项目「复验·修订建议」→ 第一卷 → 第三章「赎金」，摘要：**他把妹妹的赎金交给掌柜，换回她的自由。**
- 三个场景，场景 1 的目标还写着旧动机：**把玉佩交给掌柜**，转折：**信物被退回**。

**3. 真实模型返回**（`POST /impact/revisions`，目标=这一章）

```
status=ok  dropped=0
[0] 第1卷 第1章 场景1 | goal | 把玉佩交给掌柜 -> 把妹妹的赎金交给掌柜
[1] 第1卷 第1章 场景1 | turn | 信物被退回 -> 掌柜收下赎金并换回妹妹自由
```

两条都指向新动机，理由写的是「与本次改动的关系」，没有编造对象名（`dropped=0`）。

**4. 应用一条**

```
applied=1  skipped=0
场景1.goal == "把妹妹的赎金交给掌柜"   # 逐字相等（用 Python 读接口核对，避免 PowerShell 的 Latin-1 显示假象）
changes: [('scene', 'update', 'ai', '修订建议 · 目标')]
```

**5. 幂等**：同一 `run_id` 再应用一次 → `applied=0, skipped=1, reason=已应用`。

## 已知限制

1. **面板交互没有自动化**：勾选、应用按钮、「已变化」标红这些只有代码审查；请作者按下面 4 步手点一次。
2. **`impact_target` 只有对象现值、没有 diff**：接口只收 `target_type/target_id`，模型看到的是「现在长什么样」，不是「从什么改成了什么」。复验里靠章摘要与场景目标的矛盾推断，效果可以；真实使用中如果作者改的是上游故事圣经，建议质量取决于圣经里是否写清了新方向。
3. 候选对象上限 12，超出部分现在会计入 `dropped` 并在 warning 里说明。
4. 「全部不要」只清面板，不作废运行记录（记录留着可追溯，符合 D-03）。

## 请作者手点一次（2 分钟）

1. 打开任一章/场景的影响面面板 → 点「生成修订建议」；
2. 等 10–40 秒，看建议列表的「现在 / 建议 / 理由」是否读得懂；
3. 勾一条 → 「采纳选中 1 条」→ 对应对象的值应变化，改动历史出现「修订建议 · …」；
4. 再点一次「采纳选中」→ 应显示「已应用」而不是又写一遍。
