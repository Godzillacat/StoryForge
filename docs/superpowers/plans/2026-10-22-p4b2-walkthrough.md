## 4. 实施中值得记下的三条

1. **分支只分支正文。** 场景卡（目标 / 冲突 / 转折 / 人物 / 地点）是共享的 —— A、B 两案是同一场戏的不同写法，不是两场不同的戏。这条决定让「伏笔链接冲突」「哪张卡的锁定算数」这类没有好答案的问题根本不存在。
2. **分支的草稿直接挂在分支行上**，不建第三张表。`scene_draft` 的约束是「每场景至多一条」，与分支并存会让「采纳」与「合并」两个动作打架；挂在分支行上，丢弃分支时草稿自然消失。
3. **分支正文不进 FTS。** 索引服务的是「写这一场时该看到哪些设定」，分支是未定稿的旁路；进索引会让主版的检索命中被实验稿污染。走查里专门验了这条。
