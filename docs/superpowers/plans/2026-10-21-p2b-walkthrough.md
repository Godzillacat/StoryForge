## 2. 真实模型复验（作者库副本）

- **环境**：SQLite 备份 API 复制作者库 + `secrets.bin` 到临时目录；后端用副本启动；作者原库未写入，前后哈希一致；结束后删除副本。
- **迁移**：副本首次启动补跑 v4（`scene` 表缺失，按 `requires` 守卫跳过 SQL 并盖章，随后 `create_all` 建表）；生成 `backups/pre-migration-v4-20261021-065701/`；二次启动不重复迁移、不重复预置（7 个角色卡不变）。
- **数据**：2 项目 / 4 条目 / 2 灵感 / 1 服务商一条不少；`audit_issue` 由 `create_all` 建出；「审校」预置自动出现。
- **夹具**：作者库没有卷章结构，在**副本**里建一卷一章一场景，补正文；绑定 `qwen3.8-flash` 到审校（新建 v2，保留其余字段）。
- **正文故意埋入**：重复句；地点冲突（「北地的风沙」与「南滨旧城是南方潮湿小城」）；一句与硬规则「记忆不可彻底消失」相悖的记录。

## 3. 复验中发现的问题

### 已修复：审校预置引用空槽位导致模板失败

**现象**：真实场景没有出场人物、时间线事件与检索命中时，渲染层按结构化预置的严格模式报「提示词引用了未提供的变量」，LLM 层直接失败。审校的三个槽位天然可能为空，这不是作者的错。

**修法**（`511c10c`）：`RuntimeService.prepare_context / prepare / execute` 增加可选 `allow_missing`，默认行为不变（无契约的执笔仍放开、其它结构化预置仍严格）；审校路径显式传 `True`。补两条测试：审校路径确实传 `allow_missing=True`；其它结构化预置不传时仍严格报错。

### 限制 1：零问题的审校在重载后显示「还没有审校」

`last_audited_at` 按 spec §6.1 从该场景的问题行派生；一次没有问题的审校不产生问题行，重载后自然为空。本次会话内仍能显示「本次没有发现问题」（有警告时不显示）。修复需要给 `scene` 加列并新增迁移 v5，超出本段「不新增迁移」的约束，记为后续项。

### 限制 2：LLM 问题的特例指纹可能随 `rule_ref` 变化

spec 规定 LLM 指纹为 `llm:<kind>:<rule_ref>:<sha1(quote)>`。同一问题再次审校时若模型改写了冲突对象的表述，指纹会变化，特例抑制对 LLM 问题可能失效（规则层指纹稳定，实测抑制有效）。后续可考虑指纹只用 `kind + quote`，或对 `rule_ref` 归一化；本段按 spec 实现。

### 其它记录

- 出场人物未被提及没有可引用的正文原句，规则层 `quote` 留空；界面据此不渲染引用块。计划里「`quote` 非空」的测试条目实际只对重复句/称呼问题成立。
- 审校时间与修订时间一样，从 SQLite 读回是 naïve UTC，前端按本地时间显示（既有问题，非本段引入）。
- LLM 问题的 `target_entry_id` 只在 `rule_ref` 与条目名称/别名**精确相等**时填写；真实模型常写成整句描述，因此多为 `null`，此时「改设定 / 改人物」跳列表页。
