## 任务

### Task 1 · 静态托管（`app/static_site.py` + `main.py`）

- `dist_dir()`：按「环境变量 → `sys._MEIPASS/frontend_dist` → 仓库 `frontend/dist`」
  找第一个含 `index.html` 的目录；都没有返回 None。
- `mount_site(app)`：
  - 用 `StaticFiles` 挂 `/assets`（Vite 的产物目录）。
  - 再挂一个 catch-all：非 `/api` 且文件不存在 → 返回 `index.html`。
  - **必须在所有 API 路由注册之后调用**，否则会吞掉 `/api`。
- 找不到产物时：`/` 返回 200 + 一段可读说明（提示先跑 `pnpm build`），API 不受影响。
- 测试（`tests/test_static_site.py`）：
  - 有产物：`/` 是 index.html、`/read` 回落、`/api/health` 仍是 JSON、`/assets/x.js` 正常。
  - 无产物：`/` 说明可读、`/api/health` 仍 OK。
  - `dist_dir()` 环境变量优先。

### Task 2 · 单实例与动态端口（`app/desktop.py` 的纯逻辑部分）

- `instance.py`（或 desktop 内的纯函数）：
  ```
  read_instance() -> dict | None      # {port, pid}
  write_instance(port) -> None
  clear_instance() -> None
  port_in_use(port) -> bool
  ```
- 测试：写了能读回；端口被占用时判定在用；清理后为 None；元数据损坏时当作没有。

### Task 3 · 启动器（`app/desktop.py`）

- `--selftest`：在临时数据目录建库、建表、读一次项目列表，退出码 0。
- `--port N`：调试用固定端口。
- 正常流程：单实例检查 → 后台线程起 uvicorn（端口 0）→ 等 `/api/health` 就绪 →
  `webview.create_window(url=...)` → `webview.start()` → 退出时停服务、清理元数据。
- 后端起不来或 webview 缺失时给可读原因，不静默退出。
- **依赖**：`uv add pywebview`（仅运行外壳用；不影响后端）。

### Task 4 · PyInstaller spec

- `backend/storyforge.spec`：入口 `app/desktop.py`；datas 含 `frontend/dist`、`app/agents`、
  `app/tools_lib`；hiddenimports 含 pywebview 的 EdgeChromium 平台模块与 uvicorn 的 loop/协议实现。
- `scripts/build.ps1`：`pnpm build` → `uv run pyinstaller storyforge.spec` → 打印产物路径。
- **实测**：跑一次 PyInstaller，确认产出 `dist/StoryForge/StoryForge.exe`，
  并用 `StoryForge.exe --selftest` 验产物完整性。
